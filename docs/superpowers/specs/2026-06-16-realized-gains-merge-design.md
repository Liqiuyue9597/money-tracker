# 已实现收益按标的合并展示

## 背景

资产页（`AssetOverview`）下方的"已实现收益"区域（组件 `RealizedGainsList.tsx`）目前从 `realized_gains` 表逐条读取并展示每一次卖出操作。当用户分批次卖出同一只股票/基金/加密货币时，会出现多张卡片对应同一标的，列表显得冗长且不直观。

例如基金 `000979` 在 2026-06-08 和 2026-06-15 各卖出一次，当前显示成两张独立卡片；用户希望合并为一条记录展示。

## 目标

将同一标的的多次已实现收益合并为单条卡片展示，金额累计、百分比按累计值重算，并在卡片上指示这是多笔合并的结果。

## 非目标

- **不修改数据库**：`realized_gains` 表结构、写入逻辑、`SellDialog`、`executeSell` 等保持不动。每次卖出仍然写入一条新记录。
- **不提供展开明细**：合并后的卡片不可展开查看单笔明细（用户已选择完全合并方案）。
- **不影响其它视图**：`TransactionList`、`AnnualReport` 等模块对卖出相关交易的展示不变。

## 实现方案

仅修改前端组件 `components/RealizedGainsList.tsx`，在原有数据基础上做客户端聚合。

### 合并逻辑

按 **`symbol + asset_type`** 组合分组（同一 symbol 在不同资产类型下视为不同标的，避免极端情况下的冲突）。

每组聚合产生以下字段：

| 字段 | 计算方式 |
|---|---|
| `symbol`, `name`, `asset_type`, `currency` | 取该组中 `closed_at` 最新一条的值（`name` 可能在用户中途修改过，取最新） |
| `cost_basis` | 该组累加 |
| `proceeds` | 该组累加 |
| `realized_pnl` | 该组累加 |
| `realized_pnl_pct` | `realized_pnl / cost_basis × 100`，根据累计值重新计算（**不是**对单笔百分比求和或平均） |
| `latest_closed_at` | 该组最大的 `closed_at` |
| `count` | 该组记录数（用于卡片上显示"共 N 笔"） |
| `id` | 取最新一条的 `id`，仅作为 React `key` 用 |

聚合后的数组按 `latest_closed_at` 降序排序。

聚合逻辑放在组件内的 `useMemo` 中，依赖 `gains` 数组。

### 卡片展示变更

卡片整体结构与样式保持不变。唯一改动是底部 meta 行：

**单笔（`count === 1`）—— 与现状一致：**

```
成本 ¥5564.89 · 收入 ¥7531.00 · 2026-06-15
```

**多笔合并（`count > 1`）—— 追加"共 N 笔"：**

```
成本 ¥17272.28 · 收入 ¥23913.84 · 2026-06-15 · 共 2 笔
```

日期始终显示 `latest_closed_at`（最近一次卖出）。

### 顶部汇总卡变更

当前显示 `共 {gains.length} 笔`。改为：

- **存在合并（合并后数量 < 原始数量）：** `{合并后数量} 个标的 · 共 {原始数量} 笔卖出`
- **无合并（合并后数量 === 原始数量）：** `共 {原始数量} 笔`（保持现状）

`totalPnl` 的计算逻辑不变（仍然遍历原始 `gains` 数组，按各自的 `currency` 折算到 `mainCurrency` 后求和），因为合并不会改变总金额，只是显示分组。

### 涉及文件

- `components/RealizedGainsList.tsx` — 唯一改动文件

### 不涉及

- 数据库 schema、RPC、触发器
- `lib/swr-hooks.ts` 中的 `useRealizedGains` hook
- `lib/supabase.ts` 中的 `RealizedGain` 类型
- 其它任何组件

## 边界与正确性

- **百分比重算**：必须用 `sum(pnl) / sum(cost) × 100`，不能对单笔百分比平均。例：第一次成本 1000 赚 200（+20%），第二次成本 9000 赚 0（0%），合并后应为 `200/10000 = 2%` 而非 `(20%+0%)/2 = 10%`。
- **货币一致性**：同一 `symbol + asset_type` 的多笔卖出 `currency` 应当一致（实际数据均如此），合并时直接取最新一条的 `currency` 即可，不做跨币种合并。
- **空数组**：与现状一致，合并后数组为空时整个组件返回 `null`。
- **顶部汇总**：判断"是否存在合并"用合并前后数组长度对比，无需额外标志位。

## 测试要点

手动验证：

1. **多笔同标的合并**：基金 `000979`（已有 2 笔）在合并后应只显示 1 张卡片，金额为两笔之和，日期为 `2026-06-15`，meta 行带"共 2 笔"。
2. **单笔保持不变**：`COIN`、`DRAM` 等只卖过一次的标的，卡片显示与现状完全一致，meta 行无"共 X 笔"后缀。
3. **顶部汇总**：当前 12 条原始数据中存在合并时，应显示形如"X 个标的 · 共 12 笔卖出"。
4. **百分比正确**：基金 `000979` 两笔合并后的百分比应为 `(1966.11 + 4675.45) / (5564.89 + 11707.39) × 100 ≈ 38.45%`，而不是两笔单独百分比的平均。
5. **总收益不变**：顶部 `totalPnl` 数值与合并前完全相同（合并仅影响分组展示，不影响总和）。

## 风险

无数据风险（纯前端展示层改动）。最大风险是百分比重算实现错误，需要在测试中重点核对。
